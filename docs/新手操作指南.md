# 新手操作指南 —— 从改代码到同步 GitHub

> 这份指南假设你没有任何 Git 基础。按顺序做一遍就会了，全程约 10 分钟。
> 文中所有命令都在「项目文件夹」里执行，路径：
> `D:\桌面\外设电量显示软件_DeepSeek版`

---

## 一、先认识两个工具

### 1. 编辑器：VS Code（写代码用）

安装后用 VS Code 打开项目：**文件 → 打开文件夹 → 选 `外设电量显示软件_DeepSeek版`**。
左侧文件树里就能看到全部代码。常用文件位置：

| 你想改什么 | 改哪个文件 |
|---|---|
| 界面（窗口、卡片、托盘图标） | `app\ui\` 里的 `.py` |
| 支持哪些设备、每个设备的协议 | `app\config\devices.json` |
| 电量读取逻辑 | `app\core\protocols.py` |
| 本项目说明 | `README.md` |

改完记得 **Ctrl+S** 保存。

### 2. 终端（输入命令用）

最简单的方式：在 VS Code 里按 **Ctrl + `**（Esc 键下面那个键），底部会弹出终端。
或者：打开项目文件夹，在文件夹窗口顶部地址栏输入 `cmd` 回车。

终端打开后，先输入下面这行确认你在项目里（会显示 `(venv)` 开头）：

```
.venv\Scripts\activate
```

## 二、日常四步（改 → 测 → 提交 → 推）

以后每次改完代码，按顺序做这四件事。

### 第 1 步：跑测试（确认没改坏）

```
.venv\Scripts\python.exe -m pytest tests -q
```

**正常结果**：最后一屏显示 `274 passed`。
**如果失败**：先看报错，修好再往下走——不要提交跑挂的代码。

### 第 2 步：提交（在本地存档一个快照）

```
git add -A
git commit -m "这里写这次改了什么"
```

- `git add -A` = 把这次所有改动放进「待提交区」
- `git commit -m "..."` = 存档，引号里写人话，例如：
  - `"fix: 修复托盘图标不刷新"`
  - `"feat: 新增键盘电量显示"`

### 第 3 步：推送到 GitHub（上传）

```
git push
```

**正常结果**：显示 `main -> main`，你的仓库页面刷新就能看到。

### 第 4 步（可选）：确认推成功了

```
git status
```

显示 `up to date with origin/main` 就是同步完成。

## 三、不想记命令？用 VS Code 图形界面

VS Code 左侧竖排图标里有个「分叉」图标（源代码管理，快捷键 Ctrl+Shift+G）：

1. 改动文件会列在「更改」里
2. 顶部消息框写一句这次改了什么
3. 点 **「提交」** 按钮
4. 点 **「同步更改」** 按钮（就是一个循环箭头）

效果和命令行完全一样。

## 四、常见问题急救

| 情况 | 原因 | 解决 |
|---|---|---|
| `git push` 卡住或弹登录窗 | GitHub 要确认身份 | 按弹窗指引在浏览器点「授权」，只需一次 |
| `git status` 显示 `ahead by N commits` | 有 N 个提交忘了推 | `git push` |
| 显示 `behind` 或 `divergent` | 另一台设备推过新提交 | 先 `git pull` 再推 |
| 提交信息打错字 | — | `git commit --amend -m "正确内容"`（只改最近一条） |
| 某个文件改乱了想恢复 | — | `git restore 文件名`（恢复到最后一次提交的样子） |
| `git pull` 提示冲突 | 同一处被两边改过 | 告诉我冲突文件，我帮你合 |
| 测试突然全红 | 依赖或环境问题 | 先 `.venv\Scripts\activate` 再跑测试 |

## 五、三条红线（别做）

1. **不要删项目里的 `.git` 文件夹**——删了整个 GitHub 连接和历史都没了。
2. **不要动 `.venv` 文件夹**——那是运行环境，删了要重装几百 MB 依赖。
3. **不要把 `%APPDATA%\BatteryGlass` 里的配置提交**——你的设备清单和偏好在系统目录，本来就不在项目里，这是故意设计的（`.gitignore` 已保证它们不会被误提交）。
