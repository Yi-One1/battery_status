# 项目文件说明书 —— 每个文件是什么、怎么来的、有什么用

> 适用对象：第一次接触本项目的你。读完这份文档，你能回答三个问题：
> ① 目录里每个文件是干什么的；② 它们是怎么一步步长出来的；③ 怎么把它打包成 exe。

---

## 一、这个项目是什么

**设备电量显示**是一个 Windows 桌面小工具：常驻系统托盘，实时显示你的 2.4G/有线外设
（鼠标、键盘、耳机、手柄）的电量、连接状态和充电状态。

一句话原理：**后台线程定时通过 Windows 的 HID/USB/XInput 接口向硬件问电量 →
汇总成快照 → 界面和托盘图标照着画**。全部代码用 Python + PySide6 写成，
打包后是一个不需要安装 Python 的 exe。

## 二、目录总览

```
外设电量显示软件_DeepSeek版/
├─ main.py                  ★ 程序入口（双击/开机自启都进这里）
├─ run.bat                  一键启动（首次自动建 .venv 装依赖）

├─ LICENSE                  MIT 许可证
├─ README.md                项目门面（GitHub 首页显示它）
├─ app/                     ★ 全部源码
│  ├─ assets/               图标资源（app.ico / app.png）
│  ├─ config/devices.json   ★ 内置设备清单（支持哪些型号写在这里）
│  ├─ core/                 不画界面的“引擎层”（协议/监测/配置）
│  └─ ui/                   全部界面代码
├─ docs/                    文档（设计文档 + 新手指南 + 本文件）
```

`.venv/`（虚拟环境）和 `dist/`（打包产物）不在 Git 里，是本机生成的。

## 三、逐文件说明

### 1. 入口与启动

| 文件 | 怎么来的 | 有什么用 |
|---|---|---|
| `main.py` | 项目创建时写的第一个文件 | **总装车间**：解析启动参数（`--tray` 静默进托盘 / `--demo` 演示数据）、保证只开一个实例、把「配置+监测+界面+托盘」四块装配起来、接好开机自启。你双击 exe 时执行的就是它 |
| `run.bat` | 为新手准备的便捷启动 | 双击它：第一次自动创建 `.venv` 并装依赖，之后直接静默启动进托盘。不想敲命令就用它 |

### 2. 引擎层 `app/core/`（不画界面，但它是软件的心脏）

| 文件 | 怎么来的 | 有什么用 |
|---|---|---|
| `config.py`（592 行） | 开工第一周写的配置地基 | **两层配置体系**：内置设备模板 + 用户层增删（“墓碑”机制防止自动发现把删过的设备又加回来）；你的全部偏好（颜色、样式、顺序、托盘开关…）存在 `%APPDATA%\BatteryGlass\preferences.json` |
| `protocols.py`（849 行） | 逐台设备逆向调试出来的核心资产 | **读数协议层**：每家厂商问电量的“暗号”不同——罗技走 HID++、迈从/漫步者走厂商私有协议、飞智/手柄走 XInput。这个文件就是全部“方言词典” |
| `hidapi_io.py` | 建工程时同步写的硬件访问层 | 基于 hidapi 库枚举 HID 设备、收发数据报 |
| `hidnative.py` | 发现部分设备用标准协议就能读 | 用 Windows 原生 API 读“标准电池强度”，无需私有协议 |
| `xinput.py` | 为支持飞智手柄而加 | XInput（Windows 手柄 API）电量读取，四档：空/低/中/满 |
| `usb_port.py` | 为区分“有线/2.4G”而加 | 读注册表拿 USB 物理端口信息，判断鼠标插的是线还是接收器 |
| `discovery.py` | 「自动新增设备」功能配套 | 把系统里枚举到的一堆 HID 接口聚合成“一台物理设备”，供设置页勾选 |
| `monitor.py` | 开工时搭的骨架，后续多轮加固 | **后台监测线程**：定时扫描、失败重试、休眠判定（鼠标不动时显示“休眠中”而非“未连接”）、历史曲线 |
| `model.py` | 与 monitor 同期 | 数据模型：一次读数（Snapshot）长什么样 |
| `presence.py` | 「自动收起断连设备」功能 | 纯函数：断连超过 N 分钟就撤掉它的坑位；**设备排序（`ordered_devices`）和托盘可见性过滤也在这里**，保证面板/托盘/设置页三处口径一致 |
| `autostart.py` | 「开机自启」功能 | 写注册表 Run 项，无需管理员权限 |
| `paths.py` | 打包需求催生 | 同一份代码在“源码运行”和“打包后运行”两种环境下找到自己的文件；`APP_DISPLAY_NAME`（应用名）也在这里 |
| `demo.py` | 为无硬件演示/测试 | 生成假数据点亮界面（UI 会标注「演示」） |

### 3. 界面层 `app/ui/`

| 文件 | 怎么来的 | 有什么用 |
|---|---|---|
| `panel.py`（643 行） | 界面骨架，40+ 轮迭代 | **主面板**：无边框柔光玻璃窗口、设备卡片网格、设置页、与托盘联动、拖动/边界/尺寸自适应 |
| `glass.py`（744 行） | 「澎湃 OS 柔光玻璃」视觉重构 | **视觉引擎**：玻璃底、噪点、阴影，以及 PillButton/SegmentedControl/ToggleSwitch 等自绘控件；白色不透明模式（solid 分支）也在这 |
| `theme.py` | 与 glass 同期 | 颜色、字体、通用样式表 |
| `backdrop.py` | 玻璃效果配套 | 截桌面 → 重模糊 → 提取环境色，让玻璃“透”出桌面 |
| `gauge.py` | 三种电量样式需求 | **电量控件**：环形/条状/数字三种样式，充电绿色、告急红色、占位符闪电 |
| `cards.py` | 主面板配套 | 单设备卡片 = 一块玻璃 + 电量控件 + 名称 + 状态行 |
| `settings.py`（620 行） | 设置功能逐轮堆出来 | **设置页**：设备增删改名、颜色/样式、托盘开关、顺序调整、刷新间隔、自启动 |
| `tray.py` | 托盘功能逐轮堆出来 | **系统托盘**：每台设备一枚自绘电量图标、右键菜单、单击切面板 |
| `add_device.py` | 「新增外设」功能 | 新增设备对话框（列出检测到的设备 / 手填 VID:PID） |
| `removed_devices.py` | 「已移除设备」功能 | 删除设备的回收站：可恢复、可彻底删 |
| `confirm.py` | 防误删 | “移除设备”这类操作的二次确认弹窗 |

### 4. 设备清单 `app/config/devices.json`

**怎么来的**：每支持一台新设备，就逆向它的协议、验证读数，然后把配置加进来——目前 4 台（罗技 GPW2、飞智冰原狼 4、迈从 G98 PRO、漫步者 G3 MAX），按 4 种类型（鼠标/键盘/手柄/耳机）各带默认颜色和样式。
**有什么用**：软件认识哪些硬件、每种类型的默认外观，全写在这里。**想支持新设备就改这个文件**（协议在 `protocols.py`）。

### 5. 测试 `tests/`（274 项）

**怎么来的**：本项目纪律是「每修一个问题/加一个功能，先写测试再提交」——43 轮迭代积累出 27 个测试文件。命名规律：`test_<模块>.py` 测引擎，`test_ui_*.py` 测界面渲染，`test_protocol_*.py` 测各家协议解析，`test_*_percent/rename/order/white.py` 对应你提过的具体问题。
**有什么用**：改任何代码后跑一次 `.venv\Scripts\python.exe -m pytest tests -q`，全绿才允许提交。**这是你改代码时最重要的安全网**。

## 四、数据是怎么流动的（一条电量的旅程）

```
硬件（鼠标发一串 HID 报文）
  → hidapi_io / xinput / usb_port           （收发原始数据）
  → protocols.py                            （翻译成“电量 83%、有线、未充电”）
  → monitor.py                              （后台线程每秒级汇总成 Snapshot）
  → panel.py + tray.py                      （照着画：卡片、仪表、托盘图标）
你的眼睛 ←─────────────────────────────────┘
```

`presence.py` 在路上把关：断连太久的设备不给占位；`config.py` 在路上把关：
颜色/样式/顺序按你的偏好来。

## 五、手把手：把项目打包成 exe

> 目标：得到一份发给别人双击就能用的软件。全程约 1~2 分钟。

### 第 0 步：打开终端

VS Code 打开项目文件夹 → 按 `Ctrl + ~`。

### 第 1 步（建议）：先确认代码是健康的

```bash
.venv\Scripts\python.exe -m pytest tests -q
```

看到 `274 passed` 再往下。测试挂了说明代码有问题的，打包前先修。

### 第 2 步：执行打包

```bash
.venv\Scripts\python.exe tools\build_exe.py --onedir
```

`--onedir` = 目录版（启动快，推荐）。想要“单文件一个 exe”就去掉 `--onedir`
（启动会慢 1~3 秒，因为每次要解压）。

**预期输出**：刷一屏 `INFO:` 日志，最后出现

```
✓ 完成，产物在 D:\桌面\外设电量显示软件_DeepSeek版\dist
```

### 第 3 步：拿走产物

```
dist\设备电量显示\
├─ 设备电量显示.exe      ← 双击这个
└─ _internal\            ← 运行库，必须和 exe 放在一起，别单独拷 exe！
```

**分发/替换的规则**：整个 `设备电量显示` 文件夹一起拷贝，缺了 `_internal` 打不开。

### 第 4 步：试用

双击 `设备电量显示.exe`：
- 首次运行 Windows Defender 可能拦截 → 选「仍要运行」（自己打的包，没签名所以会问）
- 面板弹出、托盘出现图标 = 成功

### 第 5 步：日常更新软件

以后改了代码，重复第 1~3 步即可。新文件夹覆盖旧文件夹前，先退出正在运行的旧版。

## 六、打包常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| Defender 红色警告 | 个人 exe 无数字签名 | 「仍要运行」；想彻底免提示需买代码签名证书 |
| 打包中途报错 | 上次的 dist 残留 | 删掉 `dist\` 文件夹重来（脚本通常会自动清理） |
| 换电脑后 `.venv` 没了 | 环境不进 Git | 双击 `run.bat` 自动重建，或 `python -m venv .venv && .venv\Scripts\pip install -r requirements.txt` |
| exe 图标没变 | Windows 图标缓存 | 重启资源管理器或注销重登 |
| 想改 exe 名字 | — | `tools\build_exe.py --onedir --name 新名字` |
